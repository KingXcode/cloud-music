# 短音频过滤 · 0.6.2

## 使用

资料库的“短音频过滤”入口可开关过滤、输入 1–600 秒的最短时长并点“应用”。默认开启，阈值为 30 秒。取消或返回不会保存编辑中的值。关闭过滤保留之前设定的阈值，重新开启可继续使用。

- 只隐藏**已知时长小于阈值**的条目，等于阈值仍显示；未知、零或无效时长保留。
- 歌曲、专辑、歌手、搜索结果和列表数量使用同一规则。页面说明隐藏数量及未知时长数量；全被隐藏时可直接调整过滤条件。
- iCloud/系统文件、Android 本地/USB、浏览器和 Google Drive 使用相同的显示规则。切换来源不会改变设置。
- 设置仅存在本机应用/浏览器，跨设备不自动同步。浏览器清理站点存储会重置偏好。存储失败时本次使用仍生效，并提示无法持久保存。

## 时长与播放边界

Apple 原生来源在目录扫描完成后，会后台补齐系统确认已在本机的歌曲时长，未播放的短音频也会随后应用过滤。未下载或状态不明的文件仍等点播；其他来源通常在第一次播放时获得时长，已有索引中保存的时长可直接使用。Google Drive 会话在重新连接后可能再次没有时长。这不是对所有未播放短音频的立即识别保证。

过滤只计算现有元数据，**不会打开文件、请求云端音频下载、扫描音频内容、删除源文件或移除索引条目**。未知时长随后补全会重新应用显示规则；正在播放的短音频可从资料库消失，但迷你播放器、完整播放器与待播清单仍保留它。

当前功能不改播放队列、下一首、循环或自动连播行为；因此隐藏的条目仍可能出现在原待播清单并被播放。关闭过滤即可恢复显示。原有播放器和系统文件提供器在选择/播放文件时可能下载文件，这不是过滤器触发的行为。

## 实现与验证

Dart `LibraryFilter` 统一实现谓词与设置。网页使用独立 localStorage key，Apple 与 Android 使用独立的应用私有 JSON 文件和串行原子写入，不修改原曲库/歌词缓存。加载先于写入，快速保存按顺序执行，并用版本号忽略旧写入的错误提示。

自动化覆盖严格边界、未知时长、关闭/阈值恢复、损坏配置、存储失败恢复、慢加载/快速写入、旧失败提示竞态、销毁、来源切换及迟到时长；校验整个过程不发出播放、刷新或下载命令。界面覆盖歌曲/专辑/歌手/搜索、全部隐藏、取消/返回/重开、320px 手机/横屏/桌面及 1.8 倍文字。另有真实浏览器 localStorage 持久化测试，纳入现有 CI 浏览器测试步骤。

视觉检查使用测试曲库，在 Linux Flutter 渲染器中检查手机列表与面板、桌面列表及大字横屏面板。不能替代 iOS/macOS/Android 真机、SAF/USB、iCloud 和实际 Google Drive 账户测试。本地 Chrome 的既有 socket 限制未重试，浏览器测试与原生构建须以本次远程发布结果为准。
