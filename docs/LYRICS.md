# 歌词：自动匹配与离线显示

## 使用方法

打开完整播放器，点击右上角的**查看歌词**图标，或在任一播放器布局中滚动到**歌词**区域。

- **开启自动歌词**：首次说明 LRCLIB 接收的字段后，点击“同意并开启”。本机记住此选择，此后随当前歌曲自动搜索；不会整库扫描或上传音频。歌词选项中的开关可随时关闭。默认不联网。
- 优先使用本地缓存。搜索先用歌名、歌手、专辑；未找到可信版本时去掉专辑，并尝试繁简字形。手动搜索还可按歌名扩大查找；缺少歌手时也可找候选，但不自动选中。
- 歌名、完整歌手、版本标记和时长（误差不超过 3 秒）均匹配时才自动缓存。同一歌曲多份不同歌词/时间轴存在歧义时，让用户选择。专辑完全匹配的候选优先，Live、remix、伴奏等标签不被忽略。
- **搜索歌词**可手动修改标题、歌手和专辑（歌手推荐但不必填），点击“同意并搜索”后查询。结果显示歌手、专辑、时长、来源与同步类型，可筛选“仅逐行同步”。点击候选先预览，只有再点“保存到本机”才会替换。搜索期间保留已下载歌词，不自动替换手动选择或本地导入的歌词。
- **简体中文 / 保留原文**：默认简体显示，可随时切回来源原文。本地 OpenCC 字典转换中文字形，不上传歌词、不做翻译。原始文本始终保留在缓存，时间戳和偏移量不变；转换可能存在语境歧义，其他语言内容可选择保留原文。
- UTF-8 **.lrc / .txt 导入**和**粘贴**无需在线服务即可使用。导入仅替换本应用中该歌曲的歌词，不修改原始文件。
- 同步 LRC 会跟随播放进度并高亮当前行。点击某行可跳转播放，也可关闭跟随以自由浏览。纯文本歌词可滚动查看，纯音乐记录会明确显示没有歌词。
- 无匹配结果、无效元数据、限流、网络或 CORS 问题、存储失败均有各自的恢复指引。搜索失败时保留之前保存的歌词。

下载的歌词保存在**应用内离线缓存**中，不会作为伴随文件写入音乐所在目录。缓存上限约为 2 MiB / 100 首歌曲，最早保存的项目优先淘汰。大型音乐库可能需要重新下载歌词；浏览器也可能清理或淘汰存储数据。持久化失败时，会明确标记为仅在当前会话可用。清除应用或站点数据会移除此缓存，不会删除源音频。缓存绑定来源和原文件位置，后续标签补全不会丢失手动确认的歌词；自动匹配结果会按补全后的标签重新核验；文件位置变化可能需要重新选择歌词。重新选择 Apple 文件夹或通过浏览器文件输入重新选择时，应用会保守地创建新来源标识，因此旧缓存歌词需要重新选择；保留原文件夹的常规刷新和重启会保留该标识。

## 隐私与数据来源

唯一的在线服务为通过 HTTPS 访问的 `lrclib.net`，使用其公开 `/api/search` 接口。开启自动搜索后，或单次手动同意搜索后，**仅发送当前歌名、歌手及非空专辑（包括这些字段的繁简字形变体）**，不发送时长、本地文件路径、文件夹名称、音频、封面或音乐库索引。LRCLIB 必然会接收到连接的 IP 地址和客户端标识。浏览器 fetch 请求不携带凭据和来源页信息，两种适配器均拒绝重定向。本项目不代理请求，也不在服务端保存搜索历史。

缓存歌词和本地歌曲标识在原生平台保存在应用私有存储中，在 Web 端保存在当前源的浏览器本地存储中。这是普通本地存储，并非加密的机密存储。无需 API 密钥或账号。导入时仅读取用户明确选中的文件，未实现自动扫描目录或提取内嵌歌词。

### 服务接口约定与版权审查

实现时已核对以下一手资料：

- [LRCLIB 官方 API 文档](https://lrclib.net/docs.txt)：结构化搜索、最多 20 条记录、可空的同步/纯文本歌词与纯音乐标记、CORS、客户端标识、限流及 Retry-After。
- [LRCLIB 源码仓库](https://github.com/tranxuanthang/lrclib)：MIT 许可证适用于服务端软件，**不代表**其中歌词已获得版权授权。
- [LRCGET 官方客户端](https://github.com/tranxuanthang/lrcget)：下载歌词到本地是 API 的预期用途之一，但这不等同于对内容版权的全面授权。

尚未核实具有权威性的、覆盖全部歌词内容的授权，或完整适用的服务条款与隐私政策。因此不得宣传该歌词库已完成版权清理。界面会标明 LRCLIB 来源、说明内容可能不准确，并提示用户仅在获准时下载。商业再分发或应用商店分发需要另行审查内容版权与条款。本仓库不包含歌词语料库或受版权保护的歌曲测试数据，测试使用虚构文本。

## 工程实现

- `lib/lyrics/lyrics_models.dart`：带大小限制的 UTF-8、纯文本及 LRC 解析，支持多个时间戳、小数秒、含小时的时间戳、元数据、偏移量和同一时刻的歌词行分组。以冒号分隔的小数秒写法，如 `[03:24:45]`，表示 3:24.45；包含小时的格式必须带小数部分，如 `[01:02:03.250]`，以避免歧义。正的 LRC 偏移量会使歌词相对音频提前显示。空歌词提示仍保留为时间边界。
- `lib/lyrics/lyrics_controller.dart`：逐歌曲状态、一次授权的自动搜索、候选版本选择、带大小限制和版本号的缓存、过期结果防护及串行持久化。服务错误不能清空已确认的歌词。700 毫秒延迟吸收快速切歌和标签更新；同一元数据的失败/无结果自动尝试在本次会话内抑制 10 分钟，手动搜索仍可立即重试（服务限流除外）。不进行定时后台重试；对 `429`/`503` 遵循 Retry-After，因 CORS 无法读取该响应头时采用保守回退策略。
- `lib/lyrics/lyrics_native.dart`：HTTPS Dart 客户端、可识别的 User-Agent、超时、响应大小限制、原生缓存与导入桥接。
- `lib/lyrics/lyrics_web.dart`：携带 Lrclib-Client 的浏览器 fetch、遵循 CORS、超时/中止、localStorage 和浏览器文件输入，不使用 CORS 代理或绕过安全限制。
- `lib/ui/lyrics_panel.dart`：授权确认、候选筛选与预览后保存、原文/简体选项、同步高亮/滚动/跳转和离线回退。单一外层滚动避免大字体结果卡片困在固定高度的内层列表。
- `lib/lyrics/lyrics_script.dart`：随应用打包的 OpenCC 1.1.9 字典和纯 Dart 最长词组转换。繁转简采用词组优先、单字回退；简转繁搜索候选仅为单字变体，不声称完整语境翻译。字典来源、固定提交、Apache-2.0 许可和再生成脚本见 `third_party/opencc/README.md`，应用内也可查看开源许可。
- 原生 `cloud_music/control`：`readLyricsCache` -> 可空 JSON 字符串；`writeLyricsCache({value: String})` -> null；`importLyrics` -> 可空 UTF-8 字符串（null 表示取消）。缓存在应用自有存储中原子替换；输入上限为缓存 2 MiB、导入歌词 256 KiB。

Android INTERNET 权限和 macOS 客户端网络授权允许经用户同意的 HTTPS 查询。Apple 文件访问仍为只读。歌词文件选择器的取消、重复请求和组件分离独立于音乐选择器处理。

## 歌词搜索与显示优化

### 诊断与边界

2026-11-09 使用公开歌名/歌手做小样本检查（未使用用户曲库，也未保存歌词语料）：`夜曲 / 周杰伦` 返回 20 条（19 条带时间轴），`夜曲 / 周杰倫` 返回 20 条（20 条带时间轴）；加入虚构专辑 `Nonexistent QA Compilation 2026` 后返回 0 条。均为 HTTP 200。正式 Pages 来源的 CORS 预检允许 `lrclib-client`，GET 暴露 `retry-after`。这证实严格专辑条件和字形差异会影响结果，不足以证明目录完整、所有地区可达或每首歌均可下载。

修复前，手动搜索无专辑回退、必须填歌手、繁简不归一；修复后每次最多五个去重查询，顺序执行、后备请求间隔 250ms。取消、切歌和关闭自动搜索会阻止后续查询。遇到超时、网络错误、429/503 不继续盲目重试；先前已获取的候选仍可手动预览，部分失败不会自动保存。所有候选按身份/时长排序，不会仅因为带时间轴就盲选；同 ID 返回相互矛盾的时间轴仍视为歧义。

LRCLIB 的搜索目前最多返回 20 条且无分页；无结果可能是标签问题、版本差异、未收录或服务不可达。版本标记不被删除，自动保存仍要求完整歌手、歌名、版本、已知时长且差值不超过 3 秒。只有纯文本与同步记录文字完全相同且时间轴无歧义时才偏好同步记录。

### 交互依据与数据源选择

- 保持播放歌词主界面简洁，将管理收纳在选项里；按“核对歌曲 → 搜索 → 比较版本 → 预览 → 保存”的操作顺序组织。同步跳转、纯文本和本地输入入口参考 [Apple Music 的歌词交互说明](https://support.apple.com/en-lamr/guide/music/-musf438ffc97/mac)，并不假设所有歌曲都有歌词。
- 请求格式、可选字段、节流和客户端标识依据 [LRCLIB 官方文档](https://lrclib.net/docs.txt)。不是未公开的网易云/QQ 接口，没有签名逆向、反爬规避或 CORS 代理。
- [Musixmatch 官方 SDK](https://github.com/musixmatch/musixmatch-sdk)提供正式歌词接口，但本项目没有其 API 凭据及针对离线缓存/展示的已确认授权。后续增加商业数据源前须确认合同、许可、缓存范围、归属展示和部署端的密钥保护；不能直接把网页可见歌词当作可自由下载的数据源。

## 歌词字号

0.7.1 起，歌词默认字号为 22（原沉浸同步歌词 32、纯文本 30）。在歌词标题右侧点 **Aa**，可用滑块或左右 A 按钮调节为 14–36，或点“恢复默认”。字号面板有即时预览；“歌词选项”内也可调整。选择立即生效并记住本机设置，跨歌曲及横竖屏共用；无需联网或重新下载歌词。

- 同步歌词、纯文本和普通歌词面板使用同一字号，系统无障碍文字缩放仍然生效。
- 跟随播放时，字号、可用宽高或系统文字大小变化会重新对齐当前句；手动滚动暂停跟随后，调字号不会重新开启跟随。点击歌词仍按原时间戳跳转。
- 旧缓存没有字号时使用新默认值。越界值限定在 14–36，损坏的字号字段回到默认，不影响缓存内原始歌词。
- 本机存储写入失败时提示仅本次生效。设置只改变显示，不修改音频、原始歌词、繁简选择或时间轴。

### 网页时间轴修复

修复 Web 编译中 32 位移位上界导致播放进度、音频/候选时长及 LRC 时间戳被清零的问题，改用跨平台的十进制安全上界。旧缓存仍保留原始 LRC，重新读取即可恢复时间轴，无需重新下载音频或歌词。来源本身没有提供时长或时间轴时仍如实显示，不推算或伪造。

同一生产解析代码新增 Dart VM 与 dart2js/Node 双运行检查，接入 Web/发布工作流。四种来源均有模拟进度事件驱动的高亮/居中、快进/后退、暂停/恢复跟随回归；这些自动化检查不能替代 iCloud、Android、Google Drive 等真实账号与设备验收。

### 0.7.2 本地验证记录

最终合并代码通过静态分析、372 项 Flutter 单元/组件测试（12 项按环境跳过）、138 项浏览器 JavaScript 逻辑测试、6 项发布清单测试、生产解析代码的 Dart VM 与 dart2js/Node 双运行检查，以及 Web Release 构建和发布资源/Drive 延迟加载检查。额外的视觉捕获产生 16 张虚构歌词截图并完成检查。本环境未运行 Chrome 浏览器测试，未进行真实浏览器音频播放和 Android/Apple 设备验收，也没有生成新原生安装包。
