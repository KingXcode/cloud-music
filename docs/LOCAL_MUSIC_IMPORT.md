# 文件夹选择与 Android 本机扫描

## 网页

添加音乐提供「选择文件夹」和「选择多个文件」。浏览器有 `showDirectoryPicker` 时使用只读目录句柄，否则使用 `webkitdirectory` 目录输入。Safari 18.4 已加入 iPhone/iPad 的目录输入支持；不再把所有 Apple 移动设备强制降级为文件选择。明确识别到的旧版 iOS/iPadOS（18.4 以前）以及没有目录能力的浏览器保留文件多选。

文件多选始终作为独立入口保留。如果系统文件提供器限制了多选或目录选择，可换文件提供器、使用系统“文件”中的本地目录，或升级浏览器。网页只能请求多选，不能强制系统提供器接受它。目录回退可递归接收子文件夹中的音频，并保留相对路径。取消、空选择和不支持的文件不替换当前曲库；过期的选择器结果不再生效。刷新会沿用上次选择的目录或文件模式。

Safari 的目录输入不是持久目录授权。重新打开网页仍需重选；系统可能在交回列表前下载 iCloud 文件。网页既不能查询真实 iCloud 占位/下载状态，也不能保证只在点播时下载。不要将网页的“未读取”解释成“未下载”。

## Android 原生应用

- 「选择文件夹」保留现有 SAF 只读目录授权及递归扫描，适用于 Music 子目录、文件提供器和 U 盘。系统限制不能选择的根目录不尝试绕过。
- 「扫描本机音乐」是新的显式操作。Android 13+ 请求 `READ_MEDIA_AUDIO`；Android 12 及以下请求只读 `READ_EXTERNAL_STORAGE`，且清单设置 `maxSdkVersion=32`。不申请所有文件访问、照片、视频或写入权限。用户不允许也可继续用选文件夹。
- 扫描查询 MediaStore 各已挂载存储卷中标记为音乐的记录（`IS_MUSIC != 0`），只读名称、歌手、专辑、时长等已有索引。不是整盘文件爬取，不批量读取音频、不上传、不修改系统媒体库。未被系统收录或归类为音乐的音频、受限目录和未被媒体库索引的 USB 音乐，需要选择具体文件夹。
- 首次成功扫描并发现音乐后切换为「本机音乐」来源。拒绝/取消授权、空的首次扫描或查询失败都保留原曲库；已有本机音乐在重复扫描中不会重复添加。暂时消失的记录保留并标记不可用，避免拔卡或系统索引延迟造成错误清空。音频仍通过原始 `content://` URI 播放，不复制到应用沙盒。
- 重新打开应用时恢复上次来源并异步校验，不弹权限请求；只有用户主动点扫描才可弹窗。撤销权限后保留名称并说明重新授权。选择另一个文件夹、取消或新的扫描会使旧扫描结果失效。

## 跨来源取消保护

从 Google Drive 播放期间打开本地文件夹、多文件选择或 Android 扫描时，继续保留 Drive 曲库与播放。只有明确完成且发现音乐后才切换来源。关闭选择器、拒绝权限、首次扫描无结果或读取失败不打断当前播放；扫描进度及取消单独显示，失败提示可关闭。

## 自动验证和未验证范围

- 浏览器模拟测试覆盖新旧 iPhone/iPad、桌面目录选择、子目录、多文件、模式切换/恢复、取消、空结果、旧选择器回调和安全错误不自动降级。
- Flutter 测试覆盖能力解析、本机入口跨 Drive 来源路由、重复操作拦截和权限错误保留曲库。
- Android 纯 Kotlin 策略用例覆盖按版本选择权限、系统未知标签、URI 去重、跨存储卷重名文件、缺失保留和元数据合并。这不等于完整 Android 编译或权限弹窗的设备测试。

真机验收：iPhone/iPad Safari 18.4+ 选择嵌套目录并多选文件，旧版回退、系统取消、重新打开、iCloud 提前下载提示；Mac Safari 目录输入和 Chrome 持久目录；Android API 24/32/33+ 授权/拒绝/不再询问/撤销权限、首次空扫描、重复扫描、扫描中旋转/取消/切换来源、同名音乐、SD 卡拔插、后台播放；Android 系统和 USB 文件夹选择仍需独立验证。本次工作区没有 Android SDK，未做 APK 编译与上述真机验收。

依据：[WebKit Safari 18.4 目录输入](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)、[Android 共享媒体访问](https://developer.android.com/training/data-storage/shared/media)、[Android 文件及目录选择](https://developer.android.com/training/data-storage/shared/documents-files)。
